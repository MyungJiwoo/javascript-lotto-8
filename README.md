# javascript-lotto-precourse

## 📦 Model

### Lotto

> 6개의 로또 번호를 담당

- [x] 중복되지 않는 1~45 범위의 6개의 랜덤 숫자를 뽑는다.

### WinningNumbers

> 6개의 당첨 번호와, 1개의 보너스 번호를 관리하고, 추첨을 담당

- [x] 중복되지 않는 1~45 범위의 6개의 당첨 숫자를 저장한다.
  - [x] 중복이 있다면 에러 발생후 다시 입력 받는다.
  - [x] 1~45 범위의 양수가 아니라면 에러 발생 후 다시 입력 받는다.
  - [x] 당첨 번호가 6개가 아니라면 에러 발생 후 다시 입력 받는다.
- [x] 1~45 범위의 1개의 보너스 번호를 저장한다.
  - [x] 당첨 번호와 중복되면 에러 발생후 다시 입력 받는다.
  - [x] 1~45 범위의 양수가 아니라면 에러 발생 후 다시 입력 받는다.
  - [x] 1개가 아니라면 에러 발생 후 다시 입력 받는다.
- [x] Lotto의 당첨 결과를 반환한다.

### Rank

> 추첨 결과로 등수 반환을 담당

- [x] 당첨 번호와 일치한 개수와 보너스 번호 포함 여부를 전달하면 등수를 반환한다.

### Purchase

> 구매 금액과 로또 발행 개수를 담당

- [x] 로또를 구매할 금액을 1,000원 단위로 발행 가능한 로또 수량을 반환한다.
  - [x] 1,000 이상의 양수가 아니라면 에러 발생 후 다시 입력 받는다.
  - [x] 1,000 단위가 아니라면 에러 발생 후 다시 입력 받는다.

### Statistics

> 당첨 통계와 수익률 계산을 담당

- [x] 등수를 전달받아 각 등수별 몇 개씩 당첨되었는지 정리한다.
- [x] 구입한 로또 금액과 당첨금을 바탕으로 수익률을 계산한다.
  - [x] 수익률을 소수점 둘째 자리에서 반올림한다.

## 🕹️ Controller

### LottoController

- [x] 구입 금액을 입력받아 유효한 Purchase를 저장한다.
- [x] Purchase의 장수만큼 로또를 발행한다.
- [x] 발행된 로또 목록을 출력한다.
- [x] 당첨 번호(6개)를 입력받아 유효한 당첨 번호를 저장한다.
- [x] 보너스 번호를 입력받아 유효한 WinningNumbers를 완성한다.
- [x] 모든 로또의 등수를 판정하여 Statistics를 생성한다.
- [x] 등수별 개수와 상금, 수익률을 출력한다.
- [x] 프로그램을 종료한다.

## 💬 View

| Input               | 설명                                                       |
| ------------------- | ---------------------------------------------------------- |
| PurchaseInput       | 로또를 구매할 1000 단위의 금액을 문자열로 입력 받는다.     |
| WinningNumbersInput | 쉼표로 구분된 숫자 6개의 당첨 번호를 문자열로 입력 받는다. |
| BonusNumberInput    | 한 개의 보너스 번호를 문자열로 입력 받는다.                |

| Output                | 설명                         |
| --------------------- | ---------------------------- |
| PurchasedLottosOutput | 발행한 로또 내역을 출력한다. |
| WinningResultsOutput  | 로또 당첨 내역을 출력한다.   |
| YieldRateOutput       | 수익률을 출력한다.           |

## 🔎 Validation

| Validation                 | 설명                                                |
| -------------------------- | --------------------------------------------------- |
| validateIsEmpty            | 공백 및 빈 문자열은 에러를 반환한다.                |
| validateIsInteger          | 정수가 아니라면 에러를 반환한다.                    |
| validateLottoNumberCount   | 로또 개수가 6개가 아니라면 에러를 반환한다.         |
| validateUniqueLottoNumbers | 중복된 로또 번호가 있다면 에러를 반환한다.          |
| validateLottoNumberRange   | 로또 번호가 1~45 범위가 아니라면 에러를 반환한다.   |
| validateMinPurchase        | 1,000 미만이라면 에러를 반환한다.                   |
| validatePurchaseAmountUnit | 1,000 단위가 아니라면 에러를 반환한다.              |
| validateUniqueBonusNumber  | 보너스 번호가 당첨 번호와 중복되면 에러를 반환한다. |

## 🤔 느낀 점

1. **요구사항 분석을 자세하게 하자.**  
   예전에는 문제를 머리로 이해하고 바로 구현에 시작하곤 했습니다.  
   하지만 문제가 복잡해질수록 시행착오가 많이 생겼고, 컴퓨팅 사고가 필요하다는걸 느꼈습니다.  
   그래서 요구사항을 '어떻게'보다는 '무엇을'해야 하는지에 집중하고, 각 요구사항이 명확하게 O/X로 판단될 수 있는지 검증하며 분석하는 방법을 연습하고 있습니다.

2. **MVC 패턴에 도전하다.**  
   이번 미션에서는 MVC 패턴을 적극적으로 사용해보고자 노력했습니다.  
   기본적인 MVC 개념은 알고 있었지만, 코드로 구조화하는 것이 어려웠습니다. 그래서 '도메인' 단위로 접근해보았습니다.  
   예를 들어, 꼭 Class가 아니더라도 '등수'라는 뚜렷한 도메인이 있다면 Model로 구분해 구현했습니다.  
   MVC 패턴을 공부하면서 자연스럽게 js의 class 문법과 객체지향적 사고를 익힐 수 있었습니다.  
   특히 항상 고민이었던 '유효성 검사의 적절한 시점'에 대한 문제는 도메인 단위로 접근하여 인스턴스 생성 시점에 검사를 수행하면서 해결할 수 있었습니다.

3. **선언형 코드를 쓰자.**  
   함수형과 선언형의 차이점을 공부하고 선언형 코드를 쓰기 위해 노력했습니다.  
   사실 처음에는 두 방식이 단순히 구현 방법의 차이일 뿐 결국 같은 결과를 도출한다는 점에서, 선언형의 장점이 무엇일까 궁금했습니다.  
   여러 예제를 통해 함수형과 선언형을 연습했고, 실제로 구현하다보니 코드의 의도를 명확하게 드러낸다는 점이 가독성을 높이고 조금 더 유연한 코드를 만든다고 느꼈습니다.

4. **이해할 수 있는 코드를 쓰자.**  
   '이해할 수 있는 코드'를 다른 개발자와 작성자 본인 관점에 적용했습니다.  
   다른 개발자 입장에서, 주석이 없더라도 맥락만으로 파악할 수 있는 코드를 작성하려고 노력했습니다.  
   이를 위해 식별자 이름은 자세히, 매직 넘버는 최소한으로, JSDoc으로 짧은 문서화를 실천했습니다.  
   그리고 작성자 입장에서, 더 좋은 코드를 찾았어도 제가 이해한 만큼의 코드만 작성했습니다.  
   이를 통해 코드 한 줄 한 줄에 저의 의도를 담기 위해서 노력했습니다.

5. **리팩토링을 하다.**  
   처음부터 완벽한 코드를 적는 것은 현실적으로 불가능에 가깝다고 생각합니다.  
   제한된 기간 내에 최대한의 완성도를 위해서는 '일단 하자'의 마인드가 필요한 것 같습니다.  
   그래서 이번 미션에서는 기본적으로 작동하는 프로그램을 만들고 하나씩 추가하고 개선하는 방식으로 진행했습니다.
